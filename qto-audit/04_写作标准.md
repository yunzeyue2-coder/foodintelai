# FDR Writing & Decision Density Standard

## 一、核心原则

> **Decision Density：每页回答一个决策问题。**
> **Decision Density ≠ Information Density——警惕"为了看起来专业往 PDF 塞内容"。**

## 二、页面结构（一页一个闭环）

```
数据 Data
  ↓
证据 Evidence
  ↓
分析 Analysis
  ↓
结论 Conclusion
  ↓
Implication（对决策者意味着什么）
```

**反例：** "郑州炸鸡价格分布"（信息展示，没有决策）
**正例：** "20元以下是流量市场，20–30元是当前最值得验证的价格窗口吗？"（决策问题）

## 三、每页必须回答一个决策问题

页面标题必须是决策问题，不是主题名：

| ❌ 主题名 | ✅ 决策问题 |
|---------|-----------|
| 郑州炸鸡价格分布 | 20元以下是流量市场，20–30元值得验证吗？ |
| 竞争格局分析 | 正面打正新可行吗，还是必须差异化？ |
| 品牌集中度 | 结构集中≠品牌集中，这对进入意味着什么？ |
| 风险矩阵 | 什么情况必须停？停止条件是什么？ |

## 四、表述纪律（Evidence 分层）

| 证据等级 | 表述方式 |
|---------|---------|
| A 数据 | 直接引用数字，带 source/version |
| B 专家 | 必须标"行业判断"，与数据视觉分离 |
| C 框架 | "当前缺乏数据，框架如下，参数待实验校准" |
| D 未知 | 明确写"无法判断"，不猜 |
| E 验证 | "需30天实验：协议+Gate" |

## 五、禁止事项

1. **禁止编造数字**（日均100单/毛利62%——没依据就是伪精确）
2. **禁止把推断写成事实**（"多品牌存在"≠"模型已验证"）
3. **禁止为了凑章节注水**（M01-15 是 Schema，不是必写章节）
4. **禁止只给结论不给 Implication**（每页结尾必须回答"所以呢"）
5. **禁止并列使用未定义概念**（如 Brandization 与 CR5 必须区分定义）

## 六、术语使用

- 首次出现必须定义（HHI/Confidence/Archetype/Ontology）
- 决策者画像决定术语密度：无经验创业者需要术语速查页
- 专业感保留，但不以牺牲可读性为代价

## 七、诚实表达标准句

```
"当前缺乏单店经营数据，因此无法判断该品类在郑州的真实盈亏平衡点。"
"该阈值需通过30天实验校准，不由市场POI数据直接推导。"
"剩余64.8%不是'没有市场'，而是'当前数据无法形成足够确定的商业结构'。"
"结论基于可观测样本（Observable ≠ Population），不推及全市场。"
```
