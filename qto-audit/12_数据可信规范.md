# FDR 数据可信体系规范 V1.0（FDR-DATA-001）

> 定位：不是单纯"引用格式"，而是**数据可信体系设计**——让客户感觉"这个判断背后有一套严谨的数据系统，而不是 AI 随便生成"。

---

## 一、数据引用的四层目标

| 目标 | 解决 | 表现 |
| --- | --- | --- |
| 法务目标 | "你这个数字哪里来的？" | 来源可追溯 |
| 专业目标 | "为什么相信你的判断？" | 证据链完整 |
| 产品目标 | "为什么这报告值 699/1299？" | 数据资产可视化 |
| 心理目标 | "我花钱买是不是比自己查更有价值？" | 权威感/确定感/控制感 |

---

## 二、数据来源等级（Data Source Level）

### A级：权威公开数据
```
DATA SOURCE A
国家统计局 / 行业协会 / 上市公司财报
（如"2025年度餐饮收入数据"）
```

### B级：第三方商业数据
```
DATA SOURCE B
平台POI数据（美团/高德/企查查等）
采集周期：2025.10-2026.04
覆盖：郑州市
```

### C级：FoodIntelAI 模型数据（核心资产）
```
FIA MODEL DATA
FID-001 城市餐饮数据库
108350条样本
```

### D级：模型推演
```
FIA ESTIMATE
模型推演结果
非实际统计值
```

## 三、报告页面引用设计（数据卡片，非脚注）

```
┌─────────────────────────────┐
│ 郑州炸鸡市场规模             │
│                             │
│        2397 家              │
│                             │
│ 数据标签: FID-001 POI数据库  │
│ 时间: 2025.10-2026.04       │
│ 可信等级: B+                 │
│ 说明: 基于公开平台POI识别,    │
│       存在遗漏及重复可能      │
└─────────────────────────────┘
```

**视觉价值远高于普通论文引用**——普通人不会读来源说明，但会读数据卡片。

## 四、数字表达规则（防假精确）

| 类型 | 规则 | 示例 |
| --- | --- | --- |
| 原始数据 | 可以精确 | 108350条 |
| 市场估算 | 必须模糊 | ❌"386.72亿元" → ✅"约300-400亿元区间" |
| 商业模型 | 必须说明"模型测算" | ❌"净利18%" → ✅"模型测算情况下，成熟门店净利润率约15%-20%" |

## 五、数据局限声明（固定页，置于报告最后）

```
数据说明：

本报告数据来源于公开信息及 FoodIntelAI 数据库。
由于餐饮行业门店变化频繁，POI 数据存在：
- 新增未同步
- 门店关闭延迟
- 品牌识别误差

因此数据用于商业决策参考，不作为法律、财务或投资依据。
```

## 六、证据链结构（Evidence Chain）—— FDR 核心标准

**每个重要结论必须带证据链**——这是 FoodIntelAI 与普通 AI 报告的最大区别。

```markdown
❌ 观点：炸鸡适合创业。

✅ 结构：
结论：炸鸡适合小资本切入

证据：
① 市场规模：2397家门店
② 集中度：CR5 较低
③ 价格：主流 18-25元

推理：低品牌集中 + 高消费频次 + 低供应链门槛
     ↓
形成创业机会
```

## 七、产品心理三设计

### ① 权威感（数据编号系统）
```
FDR-2026-001 · Decision Engine V0.3 · FID-001 Data Source
```
客户买的不只是信息，是"做决定时更有底气"。

### ② 确定感（适合/不适合条件清单）
```
适合进入条件：
√ 资金 20万以上
√ 有运营经验
√ 接受 6个月验证

不适合：
× 高杠杆创业
× 期待快速回本
```

### ③ 控制感（行动清单）
```
未来30天：
□ 产品测试
□ 供应商筛选
□ 商圈验证

第90天：
□ 单店模型验证
```

## 九、落地检查清单（写报告时）

- [ ] 商业模型数字标注"模型测算"
