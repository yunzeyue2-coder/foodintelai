## Chapter 1 · 数据概览

- **数据量**：108,350 条**线上餐饮POI样本**（平台可见商户），40 个字段，1 个工作表"美食"
- **定位边界**：本数据集为**郑州线上餐饮生态样本**，非郑州全部餐饮市场普查——线下弱线上商户、流动经营不可见（详见 Chapter 8）
- **地理范围**：郑州市全域（含郊县：金水/二七/中原/管城/惠济/上街 + 中牟/新郑/新密/荥阳/巩义/登封）
- **内容类型**：餐饮门店 POI（位置/分类/评分/价格/菜单/营业状态）
- **关键限制**：① 跨周期采集去重快照（2025.10—2026.4），无时间维度，**不能做趋势/存活率/增长判断**；② 约半数门店无评分/价格数据；③ 数据为第三方平台口径，非官方统计
- **用途边界**：门店分布 / 品类结构 / 区域密度 / 品牌渗透 / 价格带分析；**不适用**：时段变化 / 门店存活追踪（需多期快照）

## Chapter 3 · 字段可信度评级（对接 FIE 证据等级）

> 评级原则与 FIF 证据校准一致：**证据等级决定该字段能否进入量化分析、量化到什么精度。**

| 等级 | 定义 | 本数据集字段 |
|---|---|---|
| **A** | 平台结构性数据，基本可靠，可直接建模 | id / 二类 / 三类 / name / 省 / 市 / 区 / lng / lat / 地址 / city_id / 评论数（统计值） |
| **B** | 用户贡献数据，有波动，只能区间/分布分析 | 价格（人均，用户贡献）/ 星级 / 评分（口味/环境/服务）/ 分店数 / 图片数 / 菜品数 |
| **C-** | 文本非结构化且时效性差，只能做结构参考 | 推荐菜 / 菜品 / 菜单 / tags / 榜单 / **营业时间（C-：只能做营业时段结构参考，不能做经营能力判断——餐饮营业时间极不稳定，平台数据多默认/长期未更新）** |
| **D** | 缺失严重或存在异常，暂不可用 | 营业状态（96.3%缺失）/ 其他分店（92.8%缺失+科学计数法异常）/ 路线（67.4%）/ 订座（98.8%） |
| **E** | 未知来源或无法验证 | （本数据集暂无） |

**评级说明**：B 级字段（价格/评分）虽然真实，但为用户贡献值，存在样本偏差——有价格的 61,777 家（57%）、有评分的 53,431 家（49%），**任何基于价格/评分的结论必须标注样本覆盖率**。

## Chapter 4 · 数据清洗标准

> 清洗的目的是**沉淀可复用规则**，不是一次性处理。规则对所有城市数据集通用。

| 规则 | 名称 | 处理 | 本数据集执行结果 |
|---|---|---|---|
| Rule-001 | 科学计数法恢复 | "其他分店"列长URL被Excel转成科学计数法浮点数（如 1.4699965696225e+277），需还原为字符串或置空 | 检出 **4,658 行**异常，置空处理 |
| Rule-002 | 品牌归一 | 店名含品牌关键词的归一为品牌字段（蜜雪冰城/瑞幸/锅圈等），供品牌渗透分析 | 识别出 15+ 品牌（蜜雪冰城777家/锅圈391/瑞幸382） |
| Rule-003 | 空值策略 | 按字段评级：A级字段空值→剔除；B级空值→保留并标注"无数据"；C/D级空值→保留原样 | 核心字段完整率 99.8%，A级字段无剔除 |
| Rule-004 | 重复门店 | 以 id 唯一性去重 | 108,350 条 id 全部唯一，无需去重 |
| Rule-005 | 异常价格 | 价格 <5 元或 >500 元标记为异常候选，人工复核 | 检出并标注，不直接删除（可能为套餐价/非人均） |

## Chapter 5 · 语义数据模型（Semantic Data Model）

> 定义**业务实体（Business Entity）**而非数据库表——JSON / MySQL / Neo4j / 图数据库均可按此映射，避免返工。

```
Restaurant（门店）          ← 主实体，108,350
├── name / id / 地址 / lng / lat
├── 星级 / 评论数 / 价格 / 评分
└── 营业状态 / 营业时间 / 推荐菜 / 菜品

Brand（品牌）               ← 从店名归一提取
├── 品牌名（蜜雪冰城/瑞幸/锅圈…）
└── 门店集合（1:N）

Category（品类）            ← 二类/三类
├── 二类（小吃快餐/火锅/面包饮品…）
└── 三类（快餐简餐/胡辣汤/炸鸡炸串…）

BusinessDistrict（商圈）   ← 区县+商圈
├── 区（金水/二七/中原…）
└── 商圈（板块）

Location（位置）            ← GIS
├── lng / lat / 地址
└── 用于竞争密度 / 商圈画像

ConsumerSegment（消费人群） ← derived entity · 推断实体（非原始字段）
├── 学生 / 白领 / 家庭 / 游客 / 社区居民
└── 推断来源：价格 / 位置 / 品类 / 营业时间 / 菜单
（注意：本数据集不含消费者身份数据，此实体为推断产物，证据等级 C）

BusinessOpportunity（商业机会） ← derived entity · 推断实体（非原始字段）
├── 品类缺口 / 竞争强度 / 价格空白 / 商圈机会
└── 由各引擎聚合输出，连接 FDE 决策层
（注意：机会识别属于分析产物，非数据字段，须标注证据等级）
```

**实体关系**：Restaurant 1:N Brand、1:N Category、N:1 BusinessDistrict、1:1 Location；ConsumerSegment 与 BusinessOpportunity 为推断实体（derived），由引擎生成，不属于原始数据字段。

## Chapter 6 · 质量评估（Data Quality Assessment）

> 任何数据先进质量评估，再决定能否进入 Decision Engine。

| 项目 | 得分 | 说明 |
|---|---|---|
| 完整性 | **99.8%** | 核心字段（id/名称/分类/省市/坐标/地址）空值率 <1% |
| 唯一性 | **100%** | 108,350 条 id 零重复 |
| 一致性 | 91% | 分类/行政区口径统一；异常：其他分店列 4,658 行科学计数法（已处理） |
| 空值率 | 28.1% | 全字段平均；评分/价格/星级缺失约 43-50%（样本偏差，须标注） |
| 可建模性 | **A** | 核心字段齐备，可直接支撑品类/商圈/品牌/竞争密度建模 |

**质量结论**：作为**静态结构分析**数据源质量高（可建模性 A）；作为**时序/存活追踪**数据源不合格（无时间维度，须多期快照补足）。

## Chapter 7 · Decision Engine Compatibility（决策引擎兼容性）

> FID 是 Data Layer 与 Decision Engine 之间的**接口资产**——本数据集不是决策模型，但它定义哪些字段能被哪些引擎调用、支撑什么决策能力。

| 数据实体 | 字段 | 支持能力 | 对应引擎 |
|---|---|---|---|
| Category | 二类 / 三类 | 品类竞争分析 | Category Engine |
| Location | lng / lat / 商圈 | 空间密度分析 | BusinessDistrict Engine |
| Price | 人均价格 | 价格带定位 | Position Engine |
| Review | 评论数 | 市场热度 | Competition Engine |
| Brand | 品牌识别 | 品牌渗透分析 | Competition Engine |
| Menu | 菜品文本 | 产品机会识别 | Category Engine |

**调用链**：
```
FID-001（数据层）
  ↓
Category Engine → BusinessDistrict Engine → Competition Engine → Position Engine（画像层）
  ↓
FDE 决策引擎（判断层）
  ↓
FIV 实际验证（验证层，回填校准）
```

**接口约束**：B级字段（价格/评分）进入引擎时须携带样本覆盖率，引擎输出须标注证据等级——与 FIF-37 证据校准体系一致。

## Chapter 8 · Data Boundary & Coverage Assessment（数据边界与覆盖评估）

> 数据资产的成熟度不在宣称"全"，而在**清楚知道"不全在哪里"**。本数据集定位：

**FID-001 = 郑州线上餐饮POI样本**（平台可见商户），**≠ 郑州全部餐饮市场完整数据**。

它足够支撑：品类画像（CPE）/ 竞争结构 / 区域分布 / 品牌渗透分析。
它不能支撑：真实餐饮总量 / 门店存活率 / 营业规模 / 交易活跃度。

### 数据可靠性评价（八维度）

| 维度 | 评级 | 说明 |
|---|---|---|
| 行政覆盖 | A | 覆盖郑州市域主要行政单元（6区+5县级市+1县） |
| 空间字段 | A | POI 坐标完整（lng/lat 空值率 0.5%） |
| 分类字段 | A | 适合品类分析（二/三类分级） |
| 线上门店覆盖 | B | 覆盖平台可见商户，非全量 |
| 线下隐藏商户 | C | 小区早餐店/菜市场熟食摊/老夫妻店——无线上记录，无法识别 |
| 交易真实性 | D | 无支付/交易数据（现金/微信支付不包含） |
| 时间连续性 | C | 单快照，无时间戳 |
| 经营状态 | C | 营业状态 96.3% 缺失 |

### 餐饮生态三层结构（本数据集覆盖第一层）

| 层 | 构成 | POI 可见性 |
|---|---|---|
| 第一层 | 线上平台店（美团/点评/抖音本地生活/饿了么） | ✅ 本数据集覆盖 |
| 第二层 | 线下经营但弱线上（早餐店/熟食摊/夫妻店） | ❌ 不可见 |
| 第三层 | 流动经营（夜市摊/流动摊） | ❌ POI 基本不存在 |

### 关于支付数据（微信/现金能否补足？）

支付数据 ≠ 门店数据——支付解决**交易活跃度**，POI 解决**空间存在性**，两者不替代。

### 数据融合方向（FID V2，下一阶段）

未来 FID V2 = 多源融合：

```
存在层（POI）    +  交易层（支付）  +  评价层（点评）
+  地图层（高德）  +  人口层        +  商业环境层
```

CPE 也随之升级为"品类生态画像"（当前为品类结构画像）。
